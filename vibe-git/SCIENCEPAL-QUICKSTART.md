# 第一次使用：三步接入，再完成第一轮

这是多人各用自己的 Agent、由队长统一发布和评审的科研工作区。SciencePAL 成员负责专业科研执行，Codex 成员可以独立复算、整理代码与分析结果；每个人只需准备自己使用的平台。

## 先拿到同一版本

[下载当前源码 ZIP](https://github.com/WeihanChen000/vibe-git-research/archive/refs/heads/codex/research-team-share.zip)，解压后进入其中的 `vibe-git` 子目录。电脑需要 Node.js 24+；首次打开会自动安装依赖和构建，请保留终端。不要在 ZIP 压缩预览中直接运行。

- **我是队长，房间还没开**：双击 `open-captain.cmd`。
- **我是收到邀请的队友**：双击 `open-research.cmd`。不用自己开 Host。
- **只想了解作品**：[直接看视频](https://weihanchen000.github.io/vibe-git-research/submission/watch.html)，无需安装或账号。

## ① 加入房间

队友把队长发来的邀请粘贴到本机页面。跨电脑邀请必须是队长配置的 HTTPS 地址；`localhost`、`127.0.0.1` 只能在同一台电脑演练。不要把浏览器地址栏中的本人登录链接当邀请。队长本人的身份自动接入，无需再加入自己。

## ② 绑定自己的 Agent

在右上角“算力网”（或“本机入口在线”）选择平台：

- **SciencePAL**：填写本人 Key → 验证账号并读取 Agent → 选本人可用的科研专家 → 接入算力网。浏览器已登录 SciencePAL 不等于连接器已获得 API 权限。Key 只存在本人电脑，不发给队长。
- **Codex**：选择 Codex 本地执行 → 接入算力网。后续领取任务时启动已安装并登录的 Codex；也可以复制任务说明交给自己的 Codex，完成后在同一待办交回文件。

## ③ 保存提案，然后跟着“现在轮到谁”

打开顶部“需求”页，点“我的提案”；写清研究问题、数据、本人分工、方法、单位和验收标准，点“保存我的提案”。成员保存后等待队长；队长从左上角 `vibe-git` 打开“科研项目”，选成员、上传共同数据、建立项目，再按待办对齐与发布。1CRN / Iris 只是可选示例。

### 队长接着做什么

三步只完成接入，不会自动开始实验。队长接着完成：

1. 左上角 `vibe-git → 科研项目`：勾选已就绪成员，上传共同文件，点“冻结提案并建立项目”。当前上传支持一份、不超过 256 KiB 的 UTF-8 文本数据；每个项目需要 2–4 个成员身份。
2. 打开“工作台”中的“现在轮到谁”，启动对齐；Codex 完成后仍需点“检查并交回成果”。若出现分歧，队长阅读原提案后裁决。
3. 在“协议”检查分工、方法、单位与验收。需要数值检查时，发布前配置独立参考或求和规则；没有参考答案不能随意填一个期待值。
4. 点“发布研究任务”，先核对冻结参数，展开“查看全部验收标准”，确认后发布。此后按当前待办领取、执行和评审。
5. 显示“本轮已完成”后，打开任务查看成果、评审和文件交接；只改报告时提出研究变更，由影响评审确认哪些成果可复用。

自己的提案可以按这六行准备，不必先学内部 JSON：

```text
研究问题：这次要回答什么？
输入：使用哪个文件、选择哪些数据？
分工：我负责什么，交给谁复核？
方法：使用什么方法、参数和单位？
交付：交回哪些结果、代码和原执行记录？
验收：别人如何复核？参考从哪里来、允许多大误差？
```

### 卡住时先看这里

| 看到什么 | 下一步 |
|---|---|
| 等待本人执行 / 评审 | 打开“工作台”中的“现在轮到谁”；SciencePAL 启动本人连接器，Codex 准备任务包并启动本人 Agent |
| 评审格式无效 / 评审执行失败 | 队长在“现在轮到谁”点“重试失败任务”；只重试评审，原计算成果保留，下游继续等待，不必让作者重算 |
| 建项按钮不可用 | 查看按钮前的“建项前还需要”，补齐名称、参与成员或文件来源；已选成员须各自绑定 Agent 并保存提案 |
| 更换文件失败 | 原文件和来源仍保留，但不会直接建项。重选有效文件，或明确点“继续使用原文件”；需要不带文件建项时点“移除数据文件” |
| 成果读取或核验失败 | 在原任务详情点“重新读取并核验成果”；只下载和校验原文件，不重跑计算。若仍提示字节或哈希不符，不应据此交接 |
| 复核记录读取失败 | 在原任务详情点“重新读取复核记录”；重新校验原成果和绑定记录的哈希，不启动模型。未绑定记录、文件不存在与暂时连接失败会分别说明；缺失或不符请队长核对，不能当作通过 |
| 已达到本项目运行上限 | 查看待办中的已用次数和本轮证据，由队长核对未完成项。续接与失败运行也计数；不能再返工、补证复审或重试，已派发任务仍可交回。不要重复点击或新建项目绕过原记录 |
| 评审退回 | 先看具体修改项：数值或方法有错，由队长安排返工；仅缺来源或记录且待办提供补证入口时，使用补证复审；入口不可用时先核对评审次数与额度 |
| 旧版本提交被拒绝 | 原文件保留；回到“现在轮到谁”核对当前协议与本人成员任务，使用当前任务包。不要改旧文件里的版本号冒充新成果 |
| 启动结果未知 / 连接中断 | 本人先核对原平台运行与本机日志；远端可能已开始，不能重复启动。恢复原连接器核对回执，不新建身份或任务 |
| 本地 Agent 已退出，但页面仍显示执行中 | 先核对原 Agent 进程确实停止，再在本人任务包勾选确认并点击“确认中断并恢复交回”。保留原目录和启动记录，继续完成文件后检查交回；不会重新启动模型。在当前入口仍运行的 Agent 不允许这样恢复 |
| 结果不变、仅缺证据 | 待办提供“补充证据复审”时，由队长写清来源后提交；原成果不重算，仍由独立评审者判断。同一成果已有两次评审（含无效评审）或无剩余额度时，不提供该入口 |
| 数值检查失败 | 作者按失败项修正，队长确认重试；评审写“通过”不能跳过已冻结的检查 |
| 等待本人回答 | 在本人待办点“打开本次 SciencePAL 原线程”，回答后保持连接器运行，回到本页看接续状态。若暂未取得地址，页面会明确显示查找入口；不要重新领取或新建项目 |
| 已完成 | 查看结论、原始成果、独立评审和文件交接记录 |

本机入口在线不代表模型正在执行。只有配置的数值检查通过、独立评审通过且交接依据齐全，成果才可供下游使用。没有配置的检查不等于已经核验。

跨电脑房间配置、已有房间重开、升级和故障处理见[完整接入说明](SCIENCEPAL-TEAM-START.md)。真实执行使用各自账号额度；本项目尚未完成两位真人各自账号的联合验收。

## 暂时找不到队友

可以先做[单机多成员验收](https://github.com/WeihanChen000/vibe-git-research/blob/codex/research-team-share/vibe-git/SCIENCEPAL-ISOLATED-ACCEPTANCE.md)：[已有记录可以直接回放](https://weihanchen000.github.io/vibe-git-research/replay/?case=isolated&step=members)；`npm run research:acceptance -- --live` 使用现有 Codex 和一个 SciencePAL 账号，验证真实返工、等待输入与连接器恢复。不会把它标成真人跨账号验证。

补证时请写明原任务/线程、证据来源和适用范围；可在现有文本框粘贴完整原代码与日志（最多 16000 字符）。原成果不被改写，复审仍可能退回。工具版本没有记录时如实说明，不用其他环境的版本补填。

本轮完成后，在原待办抽屉的“本轮交付”逐份下载当前获批成果、查看对应评审，并核对哪些任务有数值检查。沿用旧版的获批文件会标明来源版本；运行次数包含排队和续接，费用未获取。当前没有一键 ZIP 打包，不要把逐份下载当作完整输入/代码都已交付。

建项前的名称、成员选择、上传文件，以及未保存提案，只保存在当前页面。关闭弹层后可继续；刷新、关页或浏览器退出会丢失。先保存提案或完成建项；离开提醒不等于自动保存。
