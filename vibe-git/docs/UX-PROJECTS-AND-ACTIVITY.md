# 项目切换、直接改派与分析记录

本次改动沿用 Vue、Fastify、SQLite 和现有 CLI，不增加运行依赖。项目只有切换操作，保留原房间、任务、需求和成员；不增加结束或清空项目按钮。

## 如何使用

- 点击顶部项目名称，选择最近项目或其他目录。队长的新目录对应新房间；已有项目恢复原身份。成员只能选择已连接的项目。切换前保存需求、分工和有效的想法草稿；未提交的变更仍保留在本机缓存。
- 同时只运行当前项目的 Host。当前房间有排队或运行中的 AI 作业时，等待结束或取消后再切换。切换后旧房间暂时离线；失败时恢复原服务和配置，本机面板在切换期间保留地址与会话。
- 任务看板与任务详情使用“更换负责人”，支持单项和批量确认。操作直接更新任务包版本，保留需求版本、目标、进度与证据；新负责人同步后接续，旧负责人停止旧任务，迟到汇报不再接受。已完成、归档或被需求审核冻结的任务不能改派。
- 设置 → Codex 连接与额度下方选择“本机默认模型”。所有本机项目的 Codex 分析、对话与受管执行继承此设置；明确的本次会话覆盖优先。当前作业固定启动时模型，新设置用于后续作业。模型设置不修改其他 Codex 工具的配置，自定义 API 保留自己的模型配置。
- 右下角分析窗口显示最新活动、阶段、模型、节点与耗时，点击展开记录，按需加载更早活动。排队、工具调用、可读摘要、接收输出、校验和错误来自真实运行事件；新事件通过 SSE 更新，刷新或重连后从数据库恢复。
- 工作台的“管理成员”进入设置 → 团队成员。查看任务、改派、邀请和移除集中在这里。移除会撤销凭据、取消作业并暂停未完成任务，保留成员历史名字和完成记录；旧邀请同时失效。

## 数据与接口

房间数据保留在各项目的 `.vibe-git/host/`。本机 `projects.json` 保存项目身份与配置，仅返回名称、路径、房间 ID 和角色给网页；历史配置不保存可复用的进程 PID。`codex-model.json` 保存独立的本机模型设置。首次使用自动登记当前连接，旧房间不转换流程、不重置内容。

主要接口：

| 接口 | 用途 |
| --- | --- |
| `GET /api/local/projects` | 读取当前与已连接项目，不返回凭据 |
| `POST /api/local/projects/switch` | 以目录和当前房间 ID 切换项目，互斥并保留失败恢复 |
| `POST /api/local/projects/pick` | 本机目录选择 |
| `POST /api/v1/tasks/assign` | 按任务版本事务化改派，拒绝越权、过期和冻结任务 |
| `GET/PUT /api/local/codex/model` | 读取或保存本机默认模型 |
| `POST /api/v1/jobs/:id/status` | 作业状态与带租约、唯一 ID 的进度汇报 |
| `GET /api/v1/agile/flows/:id/activity` | 分页读取流程记录，使用 `before` 游标 |
| `POST /api/v1/join-info` | 校验邀请并读取目标房间标识，用于恢复对应的原成员身份 |

活动沿用现有 SQLite 事件表，进度不增加需求、分工或任务版本。高频输出合并，凭据过滤，长内容明确标记截断。升级前未保存的中间活动不会补造。历史房间和旧 CLI/API 流程保留。

Quick Tunnel 重启后地址可能变化。队长在团队成员中生成新邀请，成员用新地址重连；客户端仅使用目标房间的已保存身份，避免重复注册或向其他房间发送凭据。

后端与 CLI 的可运行回归检查覆盖直接改派及旧汇报拒绝、冻结任务、成员撤销与邀请轮换、进度去重与重启恢复、项目切回与启动失败恢复、并发及迟到读取隔离、真实 HTTP/SQLite 房间隔离，以及默认模型跨项目持久化和两种 Codex 执行传参。

```powershell
cd vibe-git
npm test
npm run typecheck
npm run build
```
