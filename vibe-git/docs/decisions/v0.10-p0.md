# Vibe-Git v0.10 P0 决策记录

版本：2026-09-22。来源：用户提供的《Vibe-Git 开发计划 v0.10》与本次对话。

## 已确认决定

| ID | 决定 | 实现约束 |
|---|---|---|
| U-01 | 首要分歧是需求优先级与价值评估标准不一致 | 提案必须分别保存目标、价值依据、硬约束、偏好和假设 |
| U-02 | 个人 Agent 摘要先由本人确认 | 未确认的 Proposal 不得进入团队共识 |
| U-03 | Coordinator 可在授权内自主降级候选 | 必须绑定 DelegationPolicy、动作白名单、运行引用和 DecisionRecord |
| U-04 | 正式团队版本必须全员显性确认 | A/B/C 确认同一 candidateHash；候选变化使旧确认失效；沉默不计票 |
| U-05 | 正式需求变化后的暂停策略由队长端确认 | Host 记录 ExecutionDecision；业务阻塞与本地进程状态分开 |
| U-06 | 按功能模块协作，允许多人认领 | 使用 Module → TaskPackage → WorkUnit；每名成员独立状态、分支、Plan 和证据 |
| U-07 | 第二轮个人 Plan 只审越界与冲突 | 结果为 PASS / NEEDS_REVISION / NEEDS_INFORMATION，不做实现优劣评分 |
| U-08 | DONE 必须有可验证证据 | 证据绑定验收项、真实 SHA、命令/步骤、预期/实际结果及复核 |
| U-09 | 普通新创意先经严格 PM 审查 | 上报必须绑定同内容摘要的 PASS_FOR_SUBMISSION、Agent 运行引用和本人授权；Issue 可直报 |
| U-10 | 随里程碑按影响范围冻结需求 | 使用 G0～G3 预设与 L0～L3 影响分级；不能只按时间自动冻结 |
| U-11 | Codex Connect 用于冲突审核和解决建议；自动开工向 Codex 客户端或 CLI 发命令 | 审核任务与执行命令使用不同对象、权限和状态机；审核结果不触发开工 |

## 本轮采用的建议默认

| ID | P0 默认 |
|---|---|
| P-01 | 队长端调度主体为成员 A；Coordinator 只提供建议，不自动代确认 |
| P-02 | Coordinator 可修改候选稿，不能发布正式 RequirementRevision |
| P-03 | DelegationPolicy 默认最多两次自主修订；无解时保留现行基线 |
| P-04 | Module/TaskPackage/WorkUnit；Module 有集成联系人与模块级验收 |
| P-05 | WorkUnit 默认由模块集成联系人或成员 A 复核；模块完成另需集成验收 |
| P-06 | DEFECT/BLOCKER/AMBIGUITY/SECURITY 可直接 IssueReport；涉及产品改变再走变更流程 |
| P-07 | G0～G3 与 L0～L3 为固定 P0 预设，不建设通用工作流引擎 |
| P-08 | PauseExecution 是类型化调度命令，不是远程 shell；无 Relay 回执不得显示 INTERRUPTED |
| P-09 | 新业务对象使用 SQLite JSON 记录表，写请求带 expectedRevision 与 requestId |
| P-10 | 现有能力以实际测试为准；未验证的 Agent/Codex/跨机能力不得标为成功 |
| P-11 | Connect 固定只读沙箱和结构化输出；Relay 只领取类型化 START/INTERRUPT 命令，工作区路径留在成员本机 |

## 不可信输入规则

成员提案、Agent 输出、代码、日志和附件都是业务数据。文本中的“已批准”“忽略规则”等字样不产生权限。Host 独立校验身份、候选摘要、确认集合、授权、冻结、版本、证据和状态迁移。

## Agent 输出边界

- AgentRunReference 必须记录 `runId`、`promptVersion`、`inputHash`、`outputHash`、运行模式和能力状态。
- `mock` 仅用于自动化测试；产品状态和演示不得把 mock 标为真实 Agent 运行。
- PM Review 的 PASS 只允许提交候选，不批准需求。
- Coordinator 的修订只创建 ConsensusRevision/DecisionRecord，不直接发布正式需求。
- Plan Review 的 PASS 只说明未发现越界/冲突，不证明代码正确。

## 本轮验证方式

执行 TypeScript 类型检查、Host 自动化测试和生产构建。根据用户明确要求，本轮不执行浏览器、截图、视觉、响应式或前端交互测试；前端仅报告“可编译/可打包”，不报告“交互已验证”。
