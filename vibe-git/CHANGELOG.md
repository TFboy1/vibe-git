### 审核结论：尚未完整满足需求，以下问题仍待修复

本条记录对应本轮本地实现的审核，不表示整轮验收通过。独立页面、测试和设计材料继续留在本地；其问题在此记录，方便同事统一处理。推送前发现远端同分支已有 `53158fc` 的重叠实现，该提交不在本轮审核结论覆盖范围内，整合后须重新核对受影响流程。

1. **P1：本机细化可能保存到错误任务。** `apps/cli/src/local-panel.ts` 的任务切换只更新 selected，未按任务隔离 textarea 草稿。已复现：在任务 A 写正文，切换到 B 后保存，向 B 提交了 A 的正文。修复时需要按 taskId 管理草稿，并绑定异步对话响应与保存请求的任务归属。
2. **P1：生产 Mock 开工门槛与追加范围冲突。** 用户明确要求“Mock 部分融入独立页面，其余部分实装”，当前 `apps/host/src/v20/service.ts` 和 `apps/cli/src/daemon.ts` 却让正式 CONTRACT 任务先执行 PREPARE_MOCK，且需要本机 App Server。应按用户范围收敛生产开工流程，不能把这段强制门槛视为已获验收。
3. **P1：本地独立 HTML 的 Windows 文件协议入口故障。** 本地 `apps/web/src/reviewFixture.ts` 用 URL.pathname 匹配 `/api/v1/`；file:///D:/... 下实际得到 `/D:/api/v1/...`，导致请求绕过示例数据层。已用无网络脚本复现。修复路径解析后需重新生成单文件。该示例源码和产物不包含在本次提交中。
4. **P1：本地独立页没有覆盖全部现有交互。** 已复现开始对齐、阶段契约发布、上传任务细化返回 409“当前操作暂无可用结果”；硬依赖未完成却可进入 STARTING，且缺少后续状态推进。页面确实复用生产 App、样式、开屏和三种身份，但还不能视为完整交互交付。需补齐已有控件对应的权限、版本条件与状态流转。该示例源码不包含在本次提交中。
5. **P2：模块影响未保证在队长端分析。** `apps/host/src/v20/service.ts` 的 selectAuditNode 从所有在线审核节点中按负载/额度选择，重试也可能跨节点。当前是“队长发起、审核池执行”，不完全等同于用户指定的“队长端 Agent 分析”。需按要求收敛此类作业的调度和重试范围。
6. **P2：文件所有权校验不完整。** `apps/host/src/v20/service.ts` 只比较路径字符串相等，无法识别不同负责人声明 `src/` 与 `src/shared.ts` 等重叠范围。需规范化路径，并校验目录、点段及支持的通配规则，防止共享入口重复归属。
7. **P2：本机保存细化尚非结构化确认保存。** `apps/cli/src/local-panel.ts` 只转发任意 Markdown；未对计划要求的结构化执行细节进行保存与校验。正式目标未被覆盖，但不能据此认为结构化细化已完成。
8. **P2：依赖展示仍缺上游交付详情。** `apps/web/src/App.tsx` 切片卡显示依赖状态和本任务交付物数量，尚未展示计划要求的具体上游交付物。
9. **视觉范围待核对。** 已居中的范围包括文件选择框和 empty/no-results/work-empty/schedule-empty；输入框 placeholder 没有统一居中规则。若原要求包含输入提示文字，仍需补齐。独立页未发现“仅供演示”说明，已包含一名队长、两名成员及 Agents 建设计划。

### 变更审核按钮的逻辑结论

- 无活动阶段或阶段完成时不能提交变更；普通成员不能发起或裁决审核。
- 队长需有当前阶段待审变更，且没有正在进行的审核；没有在线可用审核节点时不能发起。
- 应用/退回仅在 AWAITING_CAPTAIN；证据不足时等待成员补证，不能直接应用。
- 代码中没有“旧 UI 创建的房间导致按钮禁用”的条件。按用户要求，本项以逻辑核查为准；真实房间可能关闭，不以在线联调作为本次验收前提，也不反推当时的具体禁用原因。

- 本轮本地 Host 18 项、CLI 3 项测试及 TypeScript 检查、生产构建通过；测试材料按约定不随提交推送。这些检查没有覆盖上述全部缺陷，不能代表需求全部完成。
- 本机工作台测试覆盖了 App Server 不可用时的权限和正文隔离，尚未验证成功对话、线程恢复、异步任务归属或真实账户额度。
- 按附件计划，前端只做生产构建，不做浏览器验证；不将构建通过描述为视觉验收。

## 2026-09-23 · 房间界面与提案流程

作者：Ivan大模型

### 界面

- 调整房间总览、项目提案和工作项页面的布局、字号、配色与文案；加入新版标志和可跳过的启动动画。系统要求减少动态效果时，直接进入页面。

- 工作项增加状态、关键时间和筛选入口。

### 提案与排期

- 网页端可上传 Markdown 提案、读取当前提案、重新上传以更新，以及撤回自己的提案。每位成员在房间中只保留一份当前提案；历史修订仍由 Host 保存。
- 提交或更新前选择受影响模块并检查影响。页面提示正文明确提到的模块，以及其他提案中登记的重叠模块。重叠提示不等于内容冲突判定。
- 队长可下载、编辑并上传排期 JSON，维护模块和工作包的计划日期、状态及任务关联。成员可查看排期；Host 对更新执行队长权限、数据校验和修订号检查。
- 提案更新和撤回校验所属成员与修订号；影响检查绑定文件内容、所选模块、模块修订和当前提案集合，过期时需重新检查。原有 CLI 提交方式继续可用，未执行网页检查的提案标记为未核实。

### 接口与协作提示

- 新增 `GET /api/v1/modules`、`PUT /api/v1/modules`、`POST /api/v1/plans/impact-preview`、`DELETE /api/v1/plans/:id`；提案提交与更新接口支持影响检查结果。
- 房间 `bootstrap` 增加模块列表及其修订号；提案文档增加受影响模块和是否核实字段。部署时 Host 与网页应使用同一版本。

### 验证边界

- 本次代码已在本地构建并运行 Host/CLI 测试。真实房间的数据与公网 Host 仍需在部署后联调；甘特图需要队长录入真实排期才会显示计划条。
