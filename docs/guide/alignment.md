# 补齐需求与确认方案

## 步骤 1：启动本轮整合

> **操作人**：队长。**前置条件**：至少一份有效输入，团队算力可用，没有进行中的整合或审核。**入口**：需求 → 简述目标或导入 Markdown → 生成需求。

点击 **“生成需求”**，本机草稿会先提交，随后冻结本轮有效来源。AI 分析目标、关键缺口和真实冲突。输入无需预先写成完整规格；未提交想法的成员仍可以接任务。

已有正式需求时，可选想法页的“汇总本轮想法”将有效已提交输入纳入同一个审核批次，进入变更页。队长核对采纳/退回结论并生成新版草稿；其他待审变更留到其他批次。在需求页编辑草稿，再到任务页预览并统一发布。

**成功结果**：开始分析，已保存的输入保留。**失败处理**：无有效输入时先写目标；算力错误时检查[配置](./compute.md)，无需重复启动。**下一步**：等待分析。

## 步骤 2：等待结果

> **操作人**：队长。**前置条件**：分析已启动。**入口**：首轮在需求页，新一轮在变更页；也可使用 CLI 等待。

可以留在页面，也可以稍后返回，已提交的内容会保留。CLI 使用真实流程 ID 阻塞等待：

```powershell
vibe-git agile list
vibe-git agile wait <flow-id> 600
vibe-git agile show <flow-id>
```

`<flow-id>` 来自启动回执或 `agile list`，不能用任务 ID 代替。`wait` 最多等待 600 秒；结果需要你处理时会返回，并不一定意味着整个流程已完成。超时后作业和草稿保留，可继续等待同一流程。

**成功结果**：出现需要确认的问题，或信息充分时直接生成需求草稿。**失败处理**：失败时查看错误并点击“重试”，不频繁查询或重复启动。**下一步**：有问题执行步骤 3，已有草稿进入步骤 4。

## 步骤 3：比较选项并补齐需求

> **操作人**：队长。**前置条件**：流程正在等待回答。**入口**：首轮在需求页“补齐需求 · 比较方案”；变更审核在变更页。

1. 阅读问题原因及来源，确认缺失的信息或需要取舍的目标。
2. 每题从 **A、B、C** 三个方案中选择一个，并阅读影响说明。
3. 需要自己的方案时选 **“我有自己的方案”**，填写具体处理决定。
4. 点击 **“确认并继续”**，等待重新分析。
5. 继续处理下一题。必要时会有追问，已确认裁决可在下方历史中查看。

例如，接口是否支持删除尚有分歧，可以决定“本轮仅新增和完成，删除留到后续需求变更”，并说明这一决定对页面与接口的影响。

**成功结果**：问题记录回答，后续问题或需求草稿出现。**失败处理**：按钮不可用时先选择方案；自定义答案不能为空；版本发生变化时先读当前问题，不提交过期答案。**下一步**：确认共同需求。

## 步骤 4：打开共同需求草稿

> **操作人**：队长。**前置条件**：必要问题已回答，需求已生成。**入口**：需求页的当前草稿。

阅读需求正文，检查目标、范围、验收和裁决是否被完整保留。此时是可编辑的草稿，还没有向成员发布正式任务。

**成功结果**：需求页显示可编辑草稿。**失败处理**：仍在分析时等待；失败时按原因重试，原答案与草稿保留。**下一步**：[编辑需求、分工与发布](./dispatch.md)。

## 全程使用 CLI 时

先用 `plan submit` 提交至少一份目标或想法，再用 `vibe-git agile start` 启动首轮。已有需求后的新一轮使用工作台的“汇总本轮想法”。通过 `list/wait/show` 读取真实流程；回答、草稿和分工命令见 [CLI 参考](./reference.md#agile-cli)。CLI 和网页操作同一流程，不要重复启动。
