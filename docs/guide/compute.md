# 配置协作算力

计划整合、冲突追问、需求生成和任务分工共用这份配置。队长管理团队算力，每位成员可以检查自己的 Codex 登录与额度。

## 步骤 1：选择分析方式

> **操作人**：队长。**前置条件**：已[创建房间](./captain.md)，从本机 `vibe-git open` 进入。**入口**：Settings → 算力与 API。

选择 **“Codex 节点池”** 或 **“自定义 API”**。前者使用在线且可用的节点，后者使用队长电脑保存的 Base URL、模型和 Key。开发任务由成员当前 Agent 执行，成员无需获得队长 API Key。

**成功结果**：选定一种分析方式。**失败处理**：成员只能查看团队配置时，请队长操作。**下一步**：Codex 路径执行步骤 2，API 路径执行步骤 3。

## 步骤 2：连接本机 Codex

> **操作人**：使用 Codex 的队长或成员。**前置条件**：本机已安装 Codex CLI。**入口**：各自的 Settings → Codex 连接与额度。

1. 点击 **“刷新状态与额度”**。
2. 需要登录时点击 **“连接本机 Codex”**。
3. 按设备授权提示，由本人完成登录。
4. 再次刷新，确认“本机 Codex 已连接”。
5. 队长回到算力与 API，选择 Codex 节点池，刷新节点池后点击 **“保存设置”**。

终端命令：

```powershell
vibe-git codex status
vibe-git codex bind
vibe-git codex status
```

::: tip 新版使用本机登录
`codex bind` 使用本机默认 Codex 登录，与本机其他 Codex 客户端共享，不再创建旧文档中的隔离审核账号。需要登录时再执行，不为切换协作算力随意退出账号。
:::

**成功结果**：Codex 可用，节点池显示可用节点。额度暂不可读取不能解释成零额度。**失败处理**：先完成设备授权；仍不可用时查看具体原因、节点在线状态和网络。**下一步**：确认保存，或使用 API。

## 步骤 3：保存并测试 API

> **操作人**：队长。**前置条件**：服务支持原生 Responses 与严格 JSON Schema 输出。**入口**：队长本机 Settings → 算力与 API → 自定义 API。

1. **Base URL** 填基础地址。`https://api.openai.com/v1` 会请求 `https://api.openai.com/v1/responses`；程序只追加 `/responses`，不补 `/v1`。不要把 `/responses` 填进基础地址。
2. **模型名** 填服务及账户实际支持的名称。
3. **API Key** 填本机密码框；已有 Key 时留空可保留。
4. 点击 **“保存并测试连接”**，等待结果。
5. 确认测试通过后再开始分析；“保存设置”本身不能代替测试。

连接测试同时检查 Responses 调用与结构化输出。只支持聊天接口的服务不能直接用于当前工作流。

**成功结果**：配置保存，最近测试通过。**失败处理**：按错误检查地址、模型、Key 和结构化输出，修正后重测；Key 只填本机，不贴进聊天或提案。**下一步**：检查分析前状态。

## 步骤 4：确认分析前状态

> **操作人**：队长。**前置条件**：已配置选定方式。**入口**：Settings → 算力与 API。

刷新状态。Codex 方式确认至少一个在线可用节点，API 方式确认最近测试通过。分析失败时回答和草稿会保留，修复后可[重试](./troubleshooting.md#analysis-failed)。

**成功结果**：选定配置可用。**失败处理**：先修复配置，不连续重复点击整合。**下一步**：[提交计划](./plans.md)，再[整合](./alignment.md)。
