# 历史房间兼容

已有数据库保留原有流程，不因更新 CLI 自动转换或清库。本教程的主线针对新版房间；旧项目按原房间的真实状态继续。

## 步骤 1：识别当前房间

> **操作人**：队长和成员。**前置条件**：已经连接一个旧项目。**入口**：本人工作台及 `vibe-git status`。

确认原项目路径、房间和已有需求、任务。如果是新建的新版房间，按[主教程](../guide.md)继续；旧房间不要为了出现新版首轮按钮删除数据库。CLI 帮助包含新版命令，只说明工具有该能力，不说明历史房间已经转换。

历史记录可以在当前工作台查看，个人计划也可保留；明确启动批量审核时，该批次按工作台提供的统一审核入口处理。

**成功结果**：知道自己在继续哪个房间和流程。**失败处理**：不确定时先读取原需求、任务和当前状态，不重复创建项目。**下一步**：沿用对应的原流程。

## 原流程的入口区别

| 流程 | 需求／计划入口 | 队长操作 | 任务执行 |
| --- | --- | --- | --- |
| 新版超敏捷 | `plan submit` 首轮计划，Issues / `pr submit` 变更 | `agile` 或工作台整合、统一审核、派发 | `task inbox` 与 `task report` |
| 历史单人需求 | `intent submit` / 原提出需求入口；`change submit` 接受 JSON | 原分工与变更面板 | 按原执行方式 `task start/sync/done` |
| 旧多成员提案 | `plan submit` 原提案；`pr submit` 内部变更 | `align`、`tasks publish`、`review` | 原任务细化和执行命令 |

这里的命令组合描述不同流程，不能把它们拼成一套执行步骤。原命令字段以当前 CLI 帮助与真实房间回执为准。

## 步骤 2：查看历史参考并继续

> **操作人**：已有房间使用者。**前置条件**：已确定原流程。**入口**：原项目文档、工作台历史记录。

参考仓库[历史命令说明](https://github.com/TFboy1/vibe-git/blob/codex/frontend-rebuild/vibe-git/README.md)和[当前工作台兼容行为](https://github.com/TFboy1/vibe-git/blob/codex/frontend-rebuild/vibe-git/docs/AGILE-WORKFLOW.md)。旧版内部 PR 仍不是 GitHub 代码 PR。

**成功结果**：沿用正确入口，原任务和记录保留。**失败处理**：服务未加载新版页面或批量审核入口时，在当前作业结束后重启更新后的代码，再确认功能；不改旧报告版本来迁移任务。**下一步**：按当前工作台显示的任务包与状态继续。

## 本机 Codex 登录的变化

新版连接使用默认本机 Codex 登录。旧文档里的隔离审核目录不再作为新教程的登录方式。`codex unbind` 当前提示手动退出；`codex logout` 会影响其他本机 Codex 客户端，需要本人明确决定，不能把它当作普通房间断开操作。
