# 认识产品与身份

## 步骤 1：分清三个组成部分

> **操作人**：所有使用者。**前置条件**：准备在 Git 项目中进行团队协作。**入口**：本页，不需要先启动服务。

| 部分 | 作用 | 怎样使用 |
| --- | --- | --- |
| Skill | 告诉 Agent 怎样同步任务、操作 CLI、处理版本和汇报 | 安装后在 Agent 中加载 `vibe-git` |
| CLI | 实际启动房间、连接节点、提交 Markdown 和读取任务 | 在终端执行 `vibe-git ...` |
| 工作台 | 显示团队状态，提供需求编辑、裁决、分工和设置入口 | 在本人终端执行 `vibe-git open` |

先安装 CLI 与 Skill。以后既可以自己点工作台，也可以让当前 Agent 按 Skill 使用 CLI。网页里生成的草稿要经过队长确认与派发，才成为正式需求。

**成功结果**：知道工具各自的作用，不把 Skill 安装完成当成房间已准备好。**失败处理**：命令无法识别时转到[安装教程](./install.md)。**下一步**：选择身份。

## 步骤 2：选择队长或成员

> **操作人**：所有使用者。**前置条件**：确定由谁创建房间。**入口**：与你的队友约定身份。

- 负责创建房间和最终决定共同需求的人是**队长**，从[队长创建房间](./captain.md)开始。
- 收到邀请、在自己的电脑连接项目的人是**成员**，从[成员加入房间](./member.md)开始。
- 队长也提交自己的计划；承担开发任务时，同样按任务包汇报进度。

每位参与者使用自己的节点和工作区。相同显示名字不会合并身份，系统通过节点 ID 区分。只有队长能够执行正式整合、审核和派发。

**成功结果**：知道自己的权限和教程入口。**失败处理**：网页缺少队长按钮时先用 `vibe-git status` 检查 `node.role`，再在正确电脑运行 `vibe-git open`。**下一步**：安装工具。

## 步骤 3：确认使用的版本

> **操作人**：所有使用者。**前置条件**：准备体验本教程的新工作台。**入口**：安装教程与 CLI 帮助。

本教程对应 `codex/frontend-rebuild` 源码分支。2026-09-30 核对的 npm `0.20.0` 包仍是旧版，不包含超敏捷主线和新版任务汇报入口。

按照[能力检查](./install.md#capability-check)确认安装结果。新源码和旧 npm 包的版本号可能相同，不能只看 `0.20.0` 判断功能。

新房间默认采用新版协作；安装新 CLI 不会自动转换已有房间。已有房间请阅读[历史兼容说明](./legacy.md)。

**成功结果**：新版命令可用，本轮使用新版房间。**失败处理**：检查源码分支、构建结果与全局命令来源。**下一步**：[环境与源码安装](./install.md)。

## 贯穿教程的小例子

以“团队待办板”为例：队长负责 FastAPI 数据接口，成员负责 Vue 页面。双方提交各自计划，约定字段与验收；队长生成需求 R1 和任务包。开发中需要增加筛选能力时，成员提交需求 Issue，队长统一审核并派发 R2。

例子用于说明操作过程。实际目标、负责人、路径、ID 和验证结果均使用你自己的项目数据。
