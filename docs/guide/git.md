# 代码协作与日常维护

## 步骤 1：配置代码仓库入口

> **操作人**：使用代码协作入口的每位用户。**前置条件**：产品已有 GitHub 或 GitLab 仓库。**入口**：Settings → Git 仓库。

填写 **“仓库页面地址”**，例如你的真实 GitHub 仓库主页，点击 **“保存仓库入口”**。这份入口保存在当前浏览器；它不会替你修改本机 Git remote 或推送代码。

**成功结果**：页面显示仓库入口，“打开代码 PR”可进入托管平台。**失败处理**：地址校验失败时使用正确仓库主页；找不到源码时检查本机 `git remote -v` 与工作区。**下一步**：检查分支与改动。

## 步骤 2：提交并推送本人分支

> **操作人**：开发者。**前置条件**：有实际代码改动和仓库写权限。**入口**：产品 Git 工作区；Code 或 Pull requests 可查看已同步分支。

先检查，再按团队约定提交相关文件：

```powershell
git status
git branch --show-current
git diff
```

选择本次任务的实际文件提交并推送自己的分支，不把不相关文件、配置凭据或其他人的工作一起提交。可让 Skill 检查改动、生成提交说明并按你已授权的范围处理 Git。

工作台显示已同步的分支、提交标识和是否存在未提交改动；它不是远程托管平台的实时 PR 状态。

**成功结果**：相关代码已提交并推到正确分支。**失败处理**：权限、分支或冲突错误先在 Git 中修复；任务汇报成功不代表代码已推送。**下一步**：创建真实代码 PR。

## 步骤 3：创建、审查和合并代码 PR

> **操作人**：代码提交者与团队审查者。**前置条件**：正确分支已推送。**入口**：Pull requests → **“New pull request”**，或“查看代码 Pull requests”。

在 GitHub/GitLab 选择正确来源与目标分支，创建 PR，阅读 diff、检查验证结果并解决冲突，按团队权限与决定合并。状态、评论和最终合并结果由托管平台维护。

**成功结果**：真实代码 PR 创建、审查或合并的结果在平台可查。**失败处理**：仓库入口未配置时返回 Settings；需求本身需要改变时另提 [Issues](./changes.md)。**下一步**：同步本机代码与当前任务。

## 使用 Agents 分析与复用建议 {#agent-assistance}

> **操作人**：需要分析建议的用户。**前置条件**：本机 Codex 与工作区可用。**入口**：Agents；各页面或成员分支的“更多”→ Codex 分析／审查建议。

从当前对象进入建议，保留所选任务、Issue 或成员分支上下文。分析结果作为建议或草稿，正式计划提交、需求修改、审核和派发仍在对应页面确认。

**成功结果**：得到针对所选内容的建议。**失败处理**：本机 Codex 不可用时按[算力教程](./compute.md)连接。**下一步**：在业务页面确认并执行实际操作。

## 日常维护 {#maintenance}

### 步骤 4：检查连接与邀请

> **操作人**：队长或成员。**前置条件**：已有房间连接。**入口**：各自本机终端。

```powershell
vibe-git status
vibe-git logs
```

队长另外可用 `vibe-git host status`、`vibe-git invite show`。Quick Tunnel 重启后地址可能变化，请取得当前邀请，不继续使用旧地址。队长明确要废止旧加入链接时用 `vibe-git invite rotate`，已注册节点不因此撤销。

**成功结果**：确认当前房间、后台进程和有效邀请。**失败处理**：网络失败先保留本机草稿与报告，修复连接；不要删除房间数据库。**下一步**：重新从本机 `open` 进入，或安排正常停止。

### 步骤 5：正常停止、更新与重连

> **操作人**：停止连接的是成员；停止 Host 的是队长。**前置条件**：已经安排好当前作业与开发工作。**入口**：本机终端。

成员暂时退出用 `vibe-git disconnect`；队长停止服务用 `vibe-git host stop`。队长停止会影响成员连接，先与团队安排时机，不在分析中途随意重启。

源码更新后重新构建；队长在正确项目重新 `host start`，读取当前邀请。成员需要重连时使用当前加入命令与自己的原项目路径，再 `status`、`open` 检查。已有记录由原房间数据保留，不通过清库恢复。

**成功结果**：服务或连接按预期停止，新启动运行更新后的代码，原项目记录仍可读取。**失败处理**：重连到错误房间时先核对原项目路径和队长邀请；查看日志再处理。**下一步**：通过 Skill 同步最新任务。
