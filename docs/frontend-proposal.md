# Vibe-Git 前端业务化提案

## 提案目标

将 `apps/web` 从当前以 M0 演示为主的页面，演进为可支撑真实协作流程的前端工作台：用户能够看清房间处于哪个阶段、哪些内容已真实提交、哪些操作仍不可用，并在连接不稳定或权限不足时得到明确反馈。

本提案是面向下一轮前端迭代的增量建议，沿用现有 Host API 和协作语义，不新增后端协议，不把演示数据伪装成真实状态。

## 具体方案

### 1. 统一页面骨架与状态表达

- 保留桌面侧栏、移动端顶部导航和现有七类业务入口：房间总览、项目提案、工作项、对齐与裁决、变更审核、成员与连接、消息。
- 抽取统一的页面标题、房间标识、连接状态、刷新入口、空态、加载态和错误态组件或渲染函数。
- 所有状态使用“文字 + 颜色/图标”双重表达，不能只依赖颜色；长 ID、版本号、时间和来源信息支持复制或完整查看。
- 明确区分“未开放”“无权限”“等待同步”“暂无数据”和“操作完成”，避免用空白或演示文案代替业务状态。

### 2. 让协作流程可追踪

- 总览页展示当前阶段、成员在线情况、提案数量、任务数量和最近活动，并标明数据时间。
- 提案页支持作者最新版本、历史版本、正文、内容哈希和提交时间的查看；同一作者的修订不重复计数。
- 工作项页区分送达、已读取、等待确认、进行中、已完成等状态；不把 `WAITING_CONFIRMATION` 直接显示为完成。
- 活动记录按序号展示，并在断线重连后保持去重和顺序；同步失败时提供重试操作。
- 对齐、裁决、审核等尚未开放的能力展示只读说明和进入条件，不出现无效按钮。

### 3. 加强真实数据与错误反馈

- 所有业务卡片只使用 API 返回的数据；缺失字段显示明确的“暂无”，不使用 fixture 补齐真实场景。
- 首次进入显示加载骨架，接口失败显示可操作的错误态；刷新时保留上一次有效内容并提示“数据可能已过期”。
- 延续现有定时同步，同时兼容事件流的首次 bootstrap、事件去重、按序号重连和轮询回退。
- 提交、刷新和重连操作提供进行中、成功、失败三种反馈，避免重复点击造成重复请求。

### 4. 可访问性与响应式

- 继续支持键盘焦点、语义化按钮、对话框关闭和屏幕阅读器可识别的状态文本。
- 移动端优先保证导航、提案正文、任务状态和错误提示可读；表格或长 ID 允许横向滚动或复制。
- 动效仅用于页面切换、状态变化和反馈提示，并遵守 `prefers-reduced-motion`；不新增强制开屏或阻塞式动画。

## 实施边界

- 本轮只改前端信息架构、状态映射、渲染复用和交互反馈，不改 Host API、数据库结构或权限模型。
- 不实现本机工作区切换、统一登录迁移、通知已读接口、全屏拓扑和新的排期编辑器。
- 不引入需要额外服务部署的前端基础设施；优先在现有 `apps/web` 结构内渐进拆分，后续若进入 Vue + FastAPI 重构，再单独提交技术迁移提案。

## 验收标准

1. 前端生产构建通过，现有房间入口、提案查看、任务读取和刷新流程不回归。
2. 在真实房间中可区分加载、无数据、断线、权限不足、等待确认和完成状态。
3. 提案历史、活动序号和事件重连不会重复展示或乱序。
4. 桌面与小屏布局均能完成查看提案、查看任务状态和恢复同步三项核心操作。
5. 前端不填充虚构的成员、任务或完成比例；所有展示内容可追溯到 API 数据或明确的静态说明。

## 建议拆分

- P1：统一页面骨架、状态组件和 API 数据映射。
- P2：提案/工作项/活动页接入真实状态与同步反馈。
- P3：对齐、审核、成员、消息页面的只读状态与权限反馈。
- P4：响应式、可访问性和生产构建验收。
